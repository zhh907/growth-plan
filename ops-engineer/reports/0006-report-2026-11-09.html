二、容器网络:四个实验

① bridge = 虚拟交换机
每个容器用一对虚拟网线(veth)插进一台虚拟交换机(bridge)。同网桥的容器直接互访,不需要 -p。
本机实测网段 192.168.215.0/24(网关 .1),不是教科书的 172.17 —— OrbStack 自己划的段。
① BRIDGE = A VIRTUAL SWITCH
Each container plugs into a virtual switch via a veth pair. Containers on the same bridge reach each other directly — no -p needed.
Actual subnet here: 192.168.215.0/24 (gateway .1), not the textbook 172.17 — OrbStack allocates its own.
② -p 的守门人:OrbStack 主进程
用 lsof 抓 18080 的监听者:不是 pstub,是 OrbStack 主进程(PID 52836)。它一个进程持有所有转发端口,统一收口。
完整路径:Mac curl → OrbStack 进程 → VM → bridge → veth → 容器 eth0 → nginx。和 k8s NodePort 是同一个守门人模式。
② WHO HOLDS -p PORTS: THE ORBSTACK PROCESS
lsof on 18080: the listener is the OrbStack main process (PID 52836), not pstub. One process owns ALL forwarded ports.
Full path: Mac curl → OrbStack process → VM → bridge → veth → container eth0 → nginx. Same gatekeeper pattern as k8s NodePort.
③ 破案:容器 IP 秒通,Pod IP 超时
Mac curl 容器 IP(192.168.215.2)秒回 200:路由表里有 bridge102 直连路由,还登记了容器的 MAC —— Mac 和容器是二层邻居。
Mac curl Pod IP 超时:没有 194 段的专属路由,包掉进 192.168.0/16 大路由(utun4,VPN 隧道),进了黑洞。
结论:超时两种死法 —— 没路由被丢 / 有路但进了黑洞。路由表(netstat -rn)是判尸第一现场。
③ CASE SOLVED: CONTAINER IP FAST, POD IP TIMEOUT
curl from Mac to container IP 192.168.215.2 returns 200 instantly: the routing table has a direct bridge102 route, even listing the container's MAC — Mac and container are L2 neighbors.
curl to a Pod IP times out: no specific route for the 194 subnet, so packets fall into the broad 192.168.0/16 route (utun4, a VPN tunnel) and vanish.
Lesson: timeout has two causes — no route (dropped) or a route into a black hole. The routing table (netstat -rn) is the first crime scene.
④ inspect 结构变迁
template: ... map has no entry for key "IPAddress" 老写法 .NetworkSettings.IPAddress 在新版 Docker 报上面的错。IP 挪到了按网络分组的子结构:.NetworkSettings.Networks.bridge.IPAddress。
原因:容器可以同时接多个网络,IP 是"连接属性",不再是"容器属性"。
④ INSPECT SCHEMA CHANGE
template: ... map has no entry for key "IPAddress" The old .NetworkSettings.IPAddress fails on new Docker (OrbStack included). The IP now lives under per-network submaps: .NetworkSettings.Networks.bridge.IPAddress.
Why: a container can join several networks at once, so an IP is a property of the CONNECTION, not of the container.

三、volume:数据的生死实验

Demo 1:可写层陪葬
往容器 /tmp 写一个文件 → docker rm -f → 同镜像重建 → 文件 No such file。
镜像(只读千层饼)没变,变的是顶上那层可写黏土 —— 容器死了它陪葬。
DEMO 1: THE WRITABLE LAYER DIES WITH THE CONTAINER
Write a file to /tmp inside → docker rm -f → recreate from the same image → file gone.
The read-only image is untouched; only the writable clay layer on top was replaced — and it took the data with it.
Demo 2:named volume 幸存
docker volume create l2-data 建一块 Docker 托管的存储区(真身在 VM 的 /var/lib/docker/volumes/)。
挂到 nginx 网页根目录,写 alive.html → rm 重建 → curl 依然 200。同一套火化流程,数据活了。
附:首次挂到非空目录,Docker 会把镜像里的原内容拷进 volume,所以默认首页还在。
DEMO 2: NAMED VOLUME SURVIVES
docker volume create l2-data creates a Docker-managed storage area (real path inside the VM: /var/lib/docker/volumes/).
Mount it at nginx's docroot, write alive.html → rm & recreate → curl still 200. Same cremation, survivor this time.
Note: on first mount over a non-empty dir, Docker copies the image's content INTO the volume — that's why the default page survives too.
Demo 3:bind mount = 路径别名
把 Mac 的目录直接映射进容器(-v ~/.../site:/usr/share/nginx/html:ro)。
挂上后默认首页消失:bind mount 直接盖住目录,不拷贝 —— 和 Demo 2 行为相反。
Mac 上追加一行,curl 秒见新内容:不是同步,是同一份文件的两个名字。:ro = 容器内只读,防污染源码。
DEMO 3: BIND MOUNT = A PATH ALIAS
Map a Mac directory straight into the container (-v ~/.../site:/usr/share/nginx/html:ro).
The default page disappears: a bind mount COVERS the directory with zero copying — the exact opposite of Demo 2.
Append a line on the Mac and curl sees it instantly: not syncing — one file with two names. :ro = read-only inside, protecting source code.

四、Compose:声明式编排

从命令式到声明式
一天敲了 N 条 docker run;compose 把"要什么容器、什么网、什么卷"写进一个 yaml,一条 up -d 全拉起,一条 down 全拆光。
compose 还自动建了网络 docker-l2_default —— 我从没敲过建网命令。
这是 k8s 的预演:compose 管单机,k8s 管集群,思想同源。
IMPERATIVE → DECLARATIVE
A day of N docker run commands; compose writes "which containers, networks, volumes" into one yaml — one up -d builds all, one down removes all.
It also auto-created the network docker-l2_default — I never ran a network command.
This rehearses k8s: compose = one machine, k8s = a cluster; same idea.
按名寻址:compose 自带 DNS
probe 容器只带一个 wget,wget -qO- http://web 直接成功 —— 不用 IP,服务名就是地址。
抓回来的还是我 Mac 硬盘上的 index.html:bind mount 在 compose 里照样生效。k8s 的 Service DNS 同宗同源。
DNS BY NAME, FREE OF CHARGE
A bare alpine probe ran wget -qO- http://web and succeeded — the SERVICE NAME is the address, no IP needed.
What it fetched was the index.html on my Mac's disk: the bind mount works inside compose unchanged. k8s Service DNS is the same bloodline.
depends_on:顺序 ≠ 就绪
depends_on 只保证"先启动谁",不保证"web 端口已经在听"。probe 里 sleep 2 是土办法。
生产级的解法在 k8s 里叫 readinessProbe。这句话先背住,以后会反复遇到。
depends_on: ORDER ≠ READY
depends_on guarantees START ORDER, not that web's port is actually listening. sleep 2 is the duct-tape fix.
The production-grade cure in k8s is the readinessProbe. Memorize the slogan now; it returns.
三个真实报错,全自己修掉
① probe 缩进多 4 格,掉进 web 的肚子:报错 services.web additional properties 'probe' not allowed —— 报错直接指认了谁家门里多了谁。
② 18090 端口被 smartpeak-apollo-adminservice(工作服务)占用:不动别人,改自己 → 18095。
③ .Name → .Names:docker ps 的格式字段是复数。三错共一个套路:读报错 → 定位 → 修。
THREE REAL ERRORS, ALL SELF-FIXED
① probe indented 4 spaces too deep, landing inside web: services.web additional properties 'probe' not allowed — the error names whose door the stranger walked into.
② Port 18090 taken by smartpeak-apollo-adminservice (a work service): don't touch others — change mine → 18095.
③ .Name → .Names: docker ps format fields are plural. One shared routine: read the error → locate → fix.

五、词汇表 Vocabulary

网络
bridge — 虚拟交换机,容器组网的基本盘
veth pair — 一对虚拟网线,一头在容器一头在网桥
最长前缀匹配 — 路由选路规则:最具体的路由赢,宽路由兜底
utun4 — macOS 上 VPN 隧道的虚拟接口,本机 192.168.0/16 大路由的主人
NETWORKING
bridge — a virtual switch; the base of container networking
veth pair — a pair of virtual cables: one end in the container, one on the bridge
longest-prefix match — routing rule: the most specific route wins; broad routes are fallbacks
utun4 — macOS virtual interface for a VPN tunnel; owner of this machine's broad 192.168.0/16 route
存储
named volume — Docker 托管的存储区,数据活过容器死亡
bind mount — 宿主目录映射进容器,路径别名非复制
首挂拷贝 — named volume 挂非空目录时,镜像内容先拷入;bind mount 不拷
:ro — 只读挂载,容器内不可写
STORAGE
named volume — Docker-managed storage; data outlives the container
bind mount — host directory mapped into the container; an alias, not a copy
copy-on-first-mount — a named volume over a non-empty dir copies image content in first; bind mounts never copy
:ro — read-only mount
编排
compose service — yaml 里的一等公民,≈ 简化版 Deployment
depends_on — 只管启动顺序,不管就绪
compose DNS — 自动网络里按服务名寻址
readinessProbe — k8s 的"真就绪"检查,治 depends_on 的病
ORCHESTRATION
compose service — first-class citizen in the yaml ≈ a simplified Deployment
depends_on — start order only; says nothing about readiness
compose DNS — address services BY NAME on the auto-created network
readinessProbe — k8s' real readiness check; cures depends_on's disease
