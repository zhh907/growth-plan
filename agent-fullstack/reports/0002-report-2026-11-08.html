二、悬案复盘 The Saga: Empty Tool Input

一次教科书级排障:现象 → 观测 → 二分 → 回读代码 → 实锤 · A textbook debugging arc: symptom → observability → bisection → code review → smoking gun
① 现象:agent 陷入死循环
模型连续 4 轮调用工具、入参全是空 {},工具报"missing path",模型无限重试,被硬上限掐断。
排查第一原则:先加观测(RAW dump、逐步打印),再谈假设——循环黑盒是排障大敌。
① SYMPTOM: agent stuck in a loop
Four rounds of tool calls with EMPTY input {}; the tool raised "missing path"; the model retried forever until the hard cap fired.
First rule of debugging: add observability (raw dumps, per-step prints) BEFORE theorizing. A black-box loop is the enemy.
② 真凶:一个键名拼写(第 14 行)
工具定义里把 input_schema 写成了 input。API 对未知键静默忽略、不报错——模型收到的说明书里"参数定义"整页被撕掉,它不知道 path 存在,只能发空参。
教训:契约型接口里,键名就是合同条款。模型行为诡异时,先 dump 你发给 API 的原始请求,再怀疑基础设施——中转站这次是冤枉的。
② SMOKING GUN: one key-name typo (line 14)
The tool definition said input instead of input_schema. The API silently ignores unknown keys — the parameter page was torn out of the model's manual, so it could not know path existed.
Lesson: in contract-key interfaces, the key name IS the contract. When model behavior is bizarre, dump your raw request before blaming infrastructure — the relay was innocent this time.
③ 修复立竿见影 + 新炸点被预言
改对键名后:round 1 模型并发两个工具调用(两个文件路径全对),round 2 end_turn 给出比较结论——教科书级行为。
但 break 还没加:打印最终答案后把空 results 追加成 user 消息,round 3 发出畸形请求 → 400。没走到的分支不等于没有 bug,修好上游后它必然显形。
③ FIX WORKED INSTANTLY + PREDICTED CRASH
After the fix: round 1 issued two parallel tool calls (both paths correct); round 2 end_turn with the verdict — textbook behavior.
But break was still missing: after the final answer, empty results were appended as a user message; round 3 sent a malformed request → 400. An unexercised branch is not a correct branch — fix the upstream and it will fire.

三、报错原句精读 Error Messages

① 缺少位置参数(×7 次)
get_file_info() 缺少 1 个必需的位置参数:'path'。
要点:同一错误连发 7 次说明模型"不知道怎么修",不是"不小心"——信息缺口型错误会无限循环,必须人介入补信息。
① MISSING POSITIONAL ARGUMENT (×7)
get_file_info() missing 1 required positional argument: 'path' Takeaway: the same error seven times means the model CANNOT fix it, not that it slipped — information-gap errors loop forever until a human supplies the missing information.
② json.tool 的误导性报错
期望值:第 1 行第 1 列(字符 0)——这是 json.tool 收到空输入时的报错,不是网络错误。
要点:管道会吞掉上游的退出信息;排查时先去管道、加 -w 状态码汇报,裸看真相。
② json.tool'S MISLEADING ERROR
Expecting value: line 1 column 1 (char 0) Takeaway: this is what json.tool says when fed empty input — it is not a network error. Pipes swallow upstream signals; drop the pipe, add -w "%{http_code}"`, and look at the raw truth.
③ HTTP 000 × 0.000 秒:读时间!
HTTP 000, 0.000s, 0 bytes ——0 秒 = 连接都没尝试,不是超时(超时该是 60s)。
真因:shell 里 $BASE_URL 是空的(变量名 ANTHROPIC_BASE_URL 对不上)。
要点:状态码 000 + 耗时 0 秒 = 本地问题(变量/URL);000 + 满超时 = 网络问题。耗时是诊断字段,不只是性能字段。
③ HTTP 000 IN 0.000s: READ THE TIMING!
HTTP 000, 0.000s, 0 bytes — zero seconds means no connection was even attempted; a timeout would show the full 60s.
Root cause: $BASE_URL was empty in that shell (name mismatch with ANTHROPIC_BASE_URL).
Takeaway: status 000 + 0s = local problem (variable/URL); 000 + full timeout = network problem. Duration is a diagnostic field, not just a performance metric.
④ 上游错误:未接收到 prompt 参数
中转站转述:上游供应商拒绝了请求——因为请求最后一条消息是空的 content 数组(缺 break 导致)。
要点:"upstream_error" 的意思是"锅在我身后的供应商",但根因往往还在你的请求构造——链路长不代表锅在远处。
④ UPSTREAM ERROR: PROMPT NOT RECEIVED
400 - [1213][未正常接收到prompt参数] type: upstream_error The relay reports the provider behind it rejected the request — because the final message was an empty content array (the missing break).
Takeaway: "upstream_error" nominally means "the fault is behind me", but the root cause is usually still your request construction. A long chain does not mean the fault is far away.

四、词汇表 Vocabulary(12 terms · 3 themes)

主题 1 · 工具调用核心
input_schema 参数契约 — 工具参数 schema 必须住的键,拼错=静默失败
tool_use / tool_result — 模型发起调用 / 代码返回结果的块类型
stop_reason / end_turn — 驱动 agent 循环的控制信号
parallel tool calls 并行工具调用 — schema 清晰时模型一轮发多个调用
hard cap 硬上限 — 循环保险丝,防 token 烧穿
THEME 1 · TOOL-USE CORE
input_schema — the contract key where a tool's parameter schema must live; a typo means silent failure
tool_use / tool_result — block types: model requests a call / your code returns the outcome
stop_reason / end_turn — the control signal that drives the agent loop
parallel tool calls — model issuing several calls in ONE round when the schema lets it
hard cap — the fuse that stops infinite loops from burning tokens
主题 2 · 排障方法论
observability 可观测性 — 先让内部可见(RAW dump/逐步日志),再谈假设
smoke test 冒烟测试 — 选定依赖/模型前跑的最小标准测试
silent failure 静默失败 — 配置键写错不报错,只出灵异现象
THEME 2 · DEBUGGING DOCTRINE
observability — making internals visible (raw dumps, per-step logs) BEFORE theorizing
smoke test — a minimal standard test run before committing to a dependency or model
silent failure — a wrong config key that doesn't error, just produces haunted behavior
主题 3 · 系统与路径
CWD (current working directory) 工作目录 — 相对路径的解析参照:启动位置,不是脚本位置
shadowing 遮蔽 — 内层名字挡住外层(垃圾 import vs 自己的变量)
upstream_error 上游错误 — 中转报告"背后的供应商拒了",根因常在你自己的请求构造
verdict 结论 — 结构化输出里的最终判断字段
THEME 3 · SYSTEMS & PATHS
CWD (current working directory) — where relative paths resolve: the launch location, never the script location
shadowing — an inner name hiding an outer one (junk import vs my own variable)
upstream_error — the relay reporting the provider behind it rejected the request; the root cause is usually your own request construction
verdict — the final judgment field in a structured answer
